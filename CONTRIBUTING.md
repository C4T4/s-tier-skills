# The bar

Most lists optimise for length. This one optimises for the opposite: every entry
removed makes the rest worth more.

Five tests. All five, or it does not go in.

**1. Does one hard thing.** Not a bundle. If it needs an internal menu, it is a
collection wearing a skill's clothes.

**2. Beats the base model.** Run the task with and without. If the outputs are
comparable, it is a prompt, not a skill.

**3. Runs, doesn't advise.** Ships something that executes — a script, a checklist
with defined pass/fail, a reference with real values. "Consider whether…" is a
vibe, not a tool.

**4. Earns its context.** Worth more than the tokens it costs. Bloated preamble
counts against it.

**5. Alive, or finished.** Pushed within ~90 days, or so complete it needs no
pushes.

## Automatic rejections

- Lists of lists.
- Prompt packs renamed to skills after the fact.
- "Act as a senior engineer" with extra steps.
- Anything that can only be read, not run.
- Self-promotion where the author is the only user.

## Nominating

[Open an issue](https://github.com/C4T4/s-tier-skills/issues/new?template=nominate.yml)
and answer three things:

1. **What it does** — one sentence, a capability, no adjectives.
2. **The before/after** — the same prompt run with and without the skill. Paste
   both outputs. This decides it, and it goes in the README verbatim.
3. **Its weakest test** — and why it should still get in.

If a reader can't see the difference in five seconds, it is not an entry.
Nominations without a before/after are closed. That is not rudeness; it is the
only thing keeping the list short.

## How entries leave

Removed when the repo is archived, drifts past the maintenance line, or the base
model catches up and test 2 stops passing. The bar moves because the model moves.
